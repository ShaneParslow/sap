# Interfaces

Cap'n Proto schemas shared between programs:

- `system/`: the system's interfaces (the supervisor, the resolver, memory
  accounts, the log), and `component.capnp`, how a program defines
  itself as a component;
- `test/`: interfaces only the checks use.

A program's own schema, the struct of its bootstrap message with its
declarations, lives with the program (`user/programs/<name>/<name>.capnp`).

Rust bindings are generated by `user/lib/interfaces/build.rs`, and a
program's own by the crates that use it (`user/build_components.rs`),
without capnp-rust's RPC code.

## Calls, until RPC (M6)

A call on an interface is one IPC message on a capability to the server,
whose badge says which object it is:

- the label is the method's ordinal (`sap_interfaces::methods`);
- the words are its params struct as a single-segment message without a
  segment table (`sap_interfaces::words`), so at most 120 words;
- capability fields are left null: the capabilities travel beside the
  message by kernel capability transfer, in the order of the fields that
  name them (at most 16);
- the reply's label is the interface's status (0 for ok), its words the
  results struct, its capabilities beside it in the same way.

A call on a capability that isn't an endpoint is answered by the kernel
instead, with its error code as the label, which a server's labels can't
yet be told apart from (design/kernel.md in sap-docs).
